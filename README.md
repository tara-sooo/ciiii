# Four Rational Distances: computational search

This repository searches for a point in the Euclidean plane at rational distances from all four vertices of a unit square. The mathematical problem remains open. **Failure to find a point is not a proof of nonexistence.**

## Exact equations

A candidate P=(X/Q,Y/Q), for integers X,Y and positive Q, succeeds iff each of

```
X^2 + Y^2                 = A^2
(Q-X)^2 + Y^2             = B^2
X^2 + (Q-Y)^2             = C^2
(Q-X)^2 + (Q-Y)^2         = D^2
```

holds for integers A,B,C,D. We verify squares with integer arithmetic, not floating-point comparisons.

## Two-stage algorithm

1. `src/enumerate.cpp` enumerates **all ordered pairs of primitive Pythagorean triples** generated by Euclid parameters `2 <= m <= max_m` in the designated partition, restricting to pairs with at least one parameter `m > min_new_m` (not all rational coordinates). For triples `(a,b,h)` and `(c,d,k)` in either leg orientation, set `X=ad`, `Y=bd`, `Z=bc`, `Q=X+Z`, `V=Q-Y`. Two distances are immediately rational. For `Y<Q`, the third is rational iff `X^2+V^2` is a square, checked by exact 128-bit arithmetic after quadratic-residue sieves modulo `64, 5, 7, 11, 13`. Then test `Z^2+V^2` exactly. Persist the three-distance seeds in `seeds.json`.
2. `src/orbits.py` takes each three-distance seed and writes its primitive slope `(a,b)` with `a^2+b^2=h^2`, so P=(at,bt). Setting `sqrt(h^2*t^2-2at+1)=1+st` gives `t=2(s+a)/(h^2-s^2)`. Rationality of the third distance is equivalent to a rational point on the genus-one quartic

   ```
   w^2 = (h^2-s^2)^2 - 4*b*(s+a)*(h^2-s^2) + 4*h^2*(s+a)^2.
   ```

   A quadratic polynomial `w = lead*s^2 + B*s + C` (`lead=+1` or `-1`) tangent to the quartic at a rational point intersects the quartic at another rational point. Iteration generates large-denominator **exact** three-distance points, including points outside the square. Every generated candidate is checked against all three integer-square identities, and the fourth distance is tested exactly.


3. `src/secants.py` (opt-in local follow-up) creates rational points from **two different points on the same quartic**, rather than repeatedly taking tangents at one point. For `w^2=f(s)`, choose a quadratic `w=lead*s^2+B*s+C` with `lead=+1` or `-1` through two known rational points of different `s`. The leading quartic terms in `f(s)-(lead*s^2+B*s+C)^2` cancel. The remaining cubic has the two input rational roots, so its third root is rational. Each resulting three-distance point and its fourth squared distance are verified using exact integers. This does **not** make the search complete.

   The standalone script accepts the original `seeds-*.json` files and/or earlier compressed `points-*.jsonl.gz` orbit results. It can mix anchors from different shards when their primitive slopes match, uses only input points below configured height caps, and limits the number of secants per curve. Results are kept separate from the previous tangent-walk outputs.

The walk is not exhaustive: it visits a finite subset of rational points on specific genus-one curves. An arbitrarily small *approximation* to a rational fourth distance does not imply an exact solution.

## Run locally

```bash
g++ -O3 -std=c++20 -Wall -Wextra -o enumerate src/enumerate.cpp
./enumerate --self-test
python3 src/orbits.py --self-test
python3 src/secants.py --self-test
./enumerate --max-m=120 --output=seeds.json
python3 src/orbits.py --seeds=seeds.json --depth=5 --max-q-bits=2048
```

For a local follow-up using already generated `m<=1500` files (run in the repository root after the 900/1100/1500 batches and tangent walks have completed):

```bash
mkdir -p local-secants
python3 src/secants.py --self-test
python3 src/secants.py \\
  --seeds seeds-[0-3].json seeds-17-[0-3].json \\
          local900/seeds-*.json local1100/seeds-*.json local1500/seeds-*.json \\
  --orbits local900/orbits8192/points-*.jsonl.gz \\
           local1100/orbits8192/points-*.jsonl.gz \\
           local1500/orbits8192/points-*.jsonl.gz \\
  --tangent-depth=2 --source-bits=512 --source-q-bits=256 \\
  --per-curve=12 --pairs-per-curve=32 --max-attempts=250000 \\
  --max-q-bits=8192 \\
  --output=local-secants/summary.json \\
  --records=local-secants/points.jsonl.gz
```

A self-test passes without input files. The search prints `FOUR=<count>` at completion, or `POTENTIAL FOUR-DISTANCE SOLUTION!` immediately for any exact witness. A zero count is evidence only about the bounded candidates actually tested. Python 3.11+ integer-to-string digit limits are lifted inside `secants.py` to allow 8,192-bit denominators and larger squared-distance numerators.

## Round-aware secant follow-up (new generation)

`src/diverse_secants.py` takes previous seed/tangent/first-round points as **base** and the newest secant records as **fresh**. For each primitive slope, it picks s-distinct points spread across rational height ranges, and prioritizes fresh/base and fresh/fresh combinations. It does not spend trial budget on base/base combinations. It checks all generated three-distance and fourth-distance identities exactly, and suppresses points present in earlier compressed records. The run also writes a compressed hash ledger of attempted unordered secant pairs so a later run can skip those exact pairs using `--prior-pairs`. All search limits are finite.

```bash
mkdir -p local-secants
python3 src/diverse_secants.py --self-test
python3 src/diverse_secants.py \\
  --seeds seeds-[0-3].json seeds-17-[0-3].json \\
          local900/seeds-*.json local1100/seeds-*.json local1500/seeds-*.json \\
  --base local900/orbits8192/points-*.jsonl.gz \\
         local1100/orbits8192/points-*.jsonl.gz \\
         local1500/orbits8192/points-*.jsonl.gz \\
         local-secants/points.jsonl.gz \\
  --fresh local-secants/round2-points.jsonl.gz \\
  --source-bits=1024 --source-q-bits=2048 \\
  --per-curve=32 --pairs-per-curve=256 --max-attempts=2500000 \\
  --max-q-bits=8192 \\
  --output=local-secants/round3-summary.json \\
  --records=local-secants/round3-points.jsonl.gz \\
  --pair-log=local-secants/round3-pairs.txt.gz
```

The compressed pair ledger is for **future** trials; earlier v1/v2 runs did not record their exact tested pairs. The third-generation selection avoids base/base pairs, but it is not guaranteed that no exact pair was ever evaluated in an earlier run. The `three_distance_points` counter covers points not present in the supplied compressed base/fresh history, deduplicated within this run. Prior seed points are also excluded by their curve parameters. No complete solution is expected or claimed.

The regression test includes the known point `(45/52,24/52)` with distances `51/52`, `25/52`, `53/52`, `sqrt(833)/52`. Both programs require only a standard C++20 compiler and Python 3 standard library. Parameters and resource caps are validated.


## Changing-anchor quartic follow-up

`src/reanchor.py` changes the reference corner for each generated point.
At A it uses monic quadratic tangents. At B/C the remaining known corner
is diagonal: with `H=a*a+b*b`, `D=H-s*s`, `t=2*(s+a)/D`,
the quartic is `w*w=2*D*D-4*(a+b)*(s+a)*D+4*H*(s+a)^2`.
A quadratic tangent at one known rational point and passing through a
second known point supplies a fourth rational intersection by Vieta.
The two signed conic-distance parameters of each input provide the
initial distinct rational points whenever nondegenerate. Every resulting
coordinate is reduced and all four distances are checked using integers.

Example for the newest completed local seed band:

```bash
python3 src/reanchor.py --self-test
mkdir -p local-reanchor
python3 src/reanchor.py \
  --seeds local1800/seeds-*.json \
  --anchors ABC --depth 2 --source-bits 256 --max-q-bits 8192 \
  --max-inputs 10000 --max-points 100000 \
  --output local-reanchor/m1800-summary.json \
  --records local-reanchor/m1800-points.jsonl.gz
```

The `--points` option accepts prior orbit/secant/reanchor gzip JSONL
records. `--source-bits` bounds all three input integer coordinates,
while `--max-q-bits` bounds generated denominators. The bounded walk
deduplicates exact coordinates encountered within each run; it does not
guarantee global novelty against unprocessed earlier files. Exterior
points can serve as intermediates, but only interior four-distance
witnesses trigger the alert. Outputs are separate from the old runs;
completed files are not overwritten. A run stopped by interruption
must be restarted with its own output paths (partial files do not
constitute a checkpoint). `--anchors BC` restricts exploration to the
two new diagonal quartics. No third-party Python packages are required.


## Elliptic finite-field sieve

`src/elliptic_sieve.py` fixes a rational coordinate A/(A+B), with
positive coprime A,B and A != B. On the integer-scaled curve
`v^2=u(u+A^2)(u+B^2)`, the signed height of a doubled point is
`f(R)=(u^2-A^2*B^2)/(2*v)`. From a certified three-distance seed,
the script constructs a rational half-point by the square-root
halving formula. It explores labels `+/-f(nR)` and
`+/-AB/f(nR)` (the inversion induced by translation by the
two-torsion point). Both x- and y-coordinate models can be built.

At good odd primes (not dividing AB(A-B)(A+B)), a direct sieve tests
the two complementary square-distance conditions modulo p. A second
sieve counts compatible unordered pairs of labels whose heights
could sum to A+B, using bit masks. Poles are retained projectively;
two poles may satisfy the homogeneous sum condition. Only surviving
labels are evaluated over the rationals and all four original integer
distance identities are checked. The default mode `both` records both
sieves and verifies all direct survivors, not just labels having a
partner in the bounded list. `pairs` restricts exact checks to paired
labels, and `direct` skips pair bookkeeping.

```bash
python3 src/elliptic_sieve.py --self-test
mkdir -p local-elliptic
python3 src/elliptic_sieve.py \
  --seeds local1800/seeds-*.json \
  --axes xy --max-multiple 500 --prime-limit 251 \
  --source-bits 256 --max-curves 2000 --max-exact-bits 32768 \
  --max-exact-labels 100 --mode both \
  --output local-elliptic/m1800-summary.json \
  --records local-elliptic/m1800-curves.jsonl.gz
```

`--points` accepts existing gzip JSONL orbit, secant and reanchor
records. `--max-curves` actually caps distinct (curve, generator)
models, so several generators on the same curve may be searched;
this version does not compute Mordell-Weil ranks or mix generators.
`labels` and `pairs_before` count formal labels and unordered label
pairs (including repeated labels), not distinct rational points.
The work/label caps leave explicitly reported deferred candidates in
the per-model records; zero witnesses with deferred candidates is
not a complete check of those labels. No rank-zero exclusions or
unbounded coverage claims are made. A single curve uses a chosen
cyclic subgroup, plus inversion and sign. Degenerate fixed coordinates
0, 1 and 1/2 are skipped. The output records reflect the fixed coordinate
to the smaller of a and 1-a and may swap axes, using square symmetries.
Completed outputs are not overwritten, and partial files are not
resumable checkpoints. Python standard library only.


## Unbounded multiplier CRT sieve

`src/periodic_sieve.py` reuses the exact (curve, generator) models
from the elliptic sieve, or builds models from seeds/points. At each
good prime it computes the complete cyclic period m of the reduced
generator, not just the first N multiples. It records allowed
residues n mod m for the ordinary height f(nR) and inverse height
AB/f(nR). Negative integer n covers both signs of each height.

The generalized Chinese remainder theorem gives a finite constraint
system for all integer n. The script intersects equal periods, removes
redundant periodic structure, propagates pairwise gcd compatibility,
and uses budgeted exhaustive CRT branching if needed. An excluded
branch is a proof of impossibility for that branch of the selected
generator, with no bound on n. A surviving residue only passes these
necessary local tests. In particular the ordinary branch always
contains n divisible by every period, because poles are allowed at
good primes. It cannot be excluded by this finite set of good-prime
tests. This does not certify the existence of a rational four-distance
point. No entire-curve or Mordell-Weil rank claim is made.

```bash
python3 src/periodic_sieve.py --self-test
mkdir -p local-periodic
python3 src/periodic_sieve.py \
  --prior-models local-elliptic/m1800-curves.jsonl.gz \
  --prime-limit 251 --max-models 2000 \
  --node-cap 10000 --class-cap 1024 \
  --output local-periodic/m1800-summary.json \
  --records local-periodic/m1800-periods.jsonl.gz
```

The compressed output contains each exact model, all local periods and
allowed residues, and the CRT results. `exact_classes` indicates that
the listed residues modulo `merged_period` fully represent the
intersection, even if the raw common period is larger. Otherwise
the listed residues and density are an upper bound, and the original
local constraints still specify the exact necessary condition.
`min_abs_n_lower_bound` is a lower bound on the absolute value of any
nonzero surviving multiplier, exact when `exact_classes` is true.
`budget_limited` means satisfiability was not decided. A CRT witness
is a positive integer satisfying the congruences, not a four-distance
witness. Increasing the node/class caps increases computational cost,
not the multiplier range. No giant rational multiples are calculated.
Completed outputs are not overwritten; partial files are not
resumable checkpoints. Python standard library only.

## GitHub Actions campaign

The workflow runs daily at 02:23 UTC, on source changes to `main`, and via manual dispatch. Four shards process disjoint slices of the ordered-triple-pair search space. The scheduled campaign has **non-overlapping parameter bands** (at least one triple uses an Euclid parameter from the newly added band):

| Scheduled UTC dates | Pair coverage | Partitions |
|---|---|---|
| Nov 22–Dec 19, 2026 | all pairs with `m1,m2 <= 900` | 28 days × 4 shards |
| Dec 20, 2026–Jan 16, 2027 | `max(m1,m2)` in `(900,1100]` | 28 days × 4 shards |
| Jan 17–Mar 13, 2027 | `max(m1,m2)` in `(1100,1500]` | 56 days × 4 shards |

These three phases together cover all ordered pairs of primitive Pythagorean triples with Euclid parameters at most 1,500, in a disjoint partition, **not all rational coordinates or all bounded denominators**. Later scheduled jobs skip work. Manual runs remain configurable. The first phase alone covers about **108 billion ordered pairs** across 28 days. The initial push-triggered run is additional to the campaign.

Each job is limited to 12 minutes, and the C++ program refuses a partition with more than 4 billion pairs. The quartic walk limits the depth (5), denominator bit size (2,048 by default), and processed states (50,000). Runners are ordinary GitHub-hosted Ubuntu machines; no privileged tokens, third-party downloads, or paid services are used. The repository is public, so ordinary GitHub Actions hosted-runner minutes do not incur GitHub Actions usage charges under the current public-repo policy.

`seeds.json`, `orbits-summary.json`, compressed `orbits.jsonl.gz`, and logs are uploaded as artifacts for 30 days. The workflow marks a run as failed and prints an alert if any exact four-distance candidate is found, so the candidate can be independently checked. The YAML token permission is `contents: read`.

The complete JSONL dataset contains exact integer numerators and denominators, not just approximations. Results are never described as an exhaustive exclusion over all denominators, nor as a new theorem.
